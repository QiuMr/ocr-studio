## 可选模型库 + 主包体积 225MB → 50MB

用户拍板：**全部改为按需下载**，手动导入也要，「用户体验一定要好，进度条、各种动效」。
不要备用源（他没有）。

### 体积账（这是做决策的依据，下次别再猜）

| 部分 | 大小 | 处理 |
|---|---|---|
| exe | 17.1 MB | 必需 |
| onnxruntime + DirectML | 37.8 MB | 必需（GPU 是卖点，砍了就不是这个产品） |
| PP-OCRv6 small | 32.2 MB | **主包保留**（开箱能 OCR） |
| PP-OCRv6 medium | 133.4 MB | 按需 |
| PP-OCRv6 tiny | 7.0 MB | 按需 |
| ddddocr | 51.6 MB | 按需 |
| 提示找图两件套 | 22.4 MB | 按需 |
| 检测模型 | — | 按需（出厂仍为空） |

实测产物：zip **225.4MB → 50.3MB**（Compress-Archive，砍 78%）。
再往下只有两条路：砍推理运行时（不行），或连 small 都不带（装完啥也不能做）。

### 架构决定：下载落到 `models_root`，不新建目录

引擎层所有加载路径都是 `models_root.join(...)`。换个根目录意味着改几十处调用点，
而且极容易「本机能跑、别人机器找不到」——这是这个项目已经踩过一遍的坑。

绿色版是 zip 解压，目录通常可写，直接复用最稳。
不可写时（Program Files）报明确错误让用户换目录，不静默回退到 appdata
（回退会让 `models_root` 与实际文件位置不一致，更难排查）。

### 一个条目 = 一个 zip

PP-OCRv6 一档是 det/rec/cls + keys + meta 五个文件。逐个下发会让
「装了一半算不算装上」很难判断。打成一个 zip、解到目录，
判定退化成 `requires` 里那几个文件在不在。

### 第一红线：`rename` 跨卷会失败（实测卡住）

第一版把解压暂存目录放在 `%APPDATA%\...\downloads\_unpack_<id>`，
再 `std::fs::rename` 到 `D:\...\models\tiny`。结果：**包下好了、sha256 过了、
解压也成了（暂存目录里 5 个文件齐全），最后一步 rename 失败**，
界面停在「正在校验」不动，看不到任何错误。

根因：Windows `rename` 跨卷报 `ERROR_NOT_SAME_DEVICE`。
`%APPDATA%` 在 C:，而用户把程序解压到 D: 是极常见的情况。

修法：**暂存目录必须和目标同级**（`models/.tmp_<id>`），保证同卷内 rename。
`commit_stage()` 被 install 与 import_zip 共用，两边都改了。

### GitHub Release 必须标 prerelease

模型库挂在一个固定 tag `models` 的 Release 上（URL 才固定）：
```
releases/download/models/catalog.json
```
**但它必须 `--prerelease`**：GitHub 的 `releases/latest` 取的是「最新创建的正式
release」，模型库要是正式 release 且比版本发得晚，`releases/latest/download/latest.json`
就会指向这个没有 latest.json 的 release → 自动更新全线 404。
prerelease 不参与 latest 计算，资产照样能匿名下载。已验证 `isPrerelease: true`。

### 其他实现细节

- 清单三层兜底：网络 → 本地缓存（1h TTL）→ **内置 `assets/catalog.json`**（`include_str!`）。
  没网时也要让用户看见「这里有哪些能力可以加」，空白列表会让人以为程序坏了。
- 手动导入不强制 sha256 一致（用户可能拿到别处的等价包），但不一致要写 warn 日志。
- zip 解压做了 zip-slip 防护（`enclosed_name()`）：手动导入这条路上用户可能给任意文件。
- 手动导入需要真文件路径 → 加了 `tauri-plugin-dialog`（webview 的 `<input type=file>`
  拿不到真实路径）。capabilities 要加 `dialog:allow-open`。
- 进度事件按 1MB 节流（和更新器一致），否则事件队列本身成为瓶颈。
