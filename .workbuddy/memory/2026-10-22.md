## 第四轮：检测模型可自定义 + 类名从模型读 + 外壳浅灰

用户三点要求：① YOLO 应该能选自己的模型；② 类名最好从模型里自己读；③ 标题栏和左侧栏
换成「大家都用的那种稍微灰一点」的颜色。

### 1. 类名从 ONNX metadata 读（关键发现）
- ultralytics 导出 ONNX 时会写 model metadata：`names = "{0: 'person', 1: 'bicycle', …}"`、
  `task = detect`、`imgsz = [640, 640]`、`description`。ort 侧直接
  `sess.metadata()?.custom("names")` 就能拿（`ort 2.0.0-rc.15` 的 `ModelMetadata::custom`）。
- **不需要 labels.txt**。优先级：metadata > labels.txt（同目录 / 同名 .txt）> `class_{id}`。
- `names` 是 Python dict 的 repr，要自己解析：数字 key、单/双引号、`\'` 转义、
  乱序 key、值里带数字（`'person 2'`）。写了个小状态机 `parse_names`，7 个单测。
- **顺带用 `task` 拦非检测模型**：segment/pose/obb 的输出多 32 个 mask 系数或关键点通道，
  按 `4+classes` 解不会崩、只会给错类别的框 —— 比报错难查得多。
- 实测：把 `labels.txt` 整个移走，检测仍输出 person/bus（证明走的是 metadata）。

### 2. 多模型 + 任意路径
- `catalog::list_yolo_models(root, external)`：扫 `detect/yolo/` 下**所有** `*.onnx`
  （含一层子目录），再并上 config 的 `detect_models`（绝对路径列表）。
- id = 文件名；撞名退到「父目录/文件名」再撞加序号。**第一个 = 默认模型**，
  spec 用不带 id 的 `yolo`（与 `/engine/list`、前端下拉缺省值、pipeline 缺省值一致）。
- **外部模型名不能「像版本号」**（如 `v8.onnx`）——`EngineSpec::parse` 会把 `yolo:v8`
  当旧写法吃掉，所以 `unique_id` 对 external 跳过这类 id。
- 文件选择框用 Win32 `GetOpenFileNameW`（windows crate feature
  `Win32_UI_Controls_Dialogs`）。**`lpstrDefExt` 必须先绑变量**：
  `PCWSTR::from_raw(wide("onnx").as_ptr())` 会指向已 drop 的临时 Vec。
- `save_config` 里必须**保留后端自己维护的 `detect_models`**（前端带的是旧快照），
  否则「刚加的模型」会被下一次保存冲掉。与 `webview_compat` 同理。

### 3. 类名回填（不加载模型就读不到）
- `/engine/list` 是纯目录扫描，读不到 metadata 里的类名（要建 session 才行，几秒+显存）。
- 新增 `AppState::engine_status_list()`，**HTTP 与 IPC 共用一份**（原来两处几乎重复，
  很容易只改一处导致两端不一致）。引擎加载过后回填 classes + 把 note 里的
  「类名在加载时读取」换成「已加载 N 类」。

### 4. 外壳配色
- `styles.css` 加 `--color-chrome: #f7f7f8`（Tailwind v4 @theme → `bg-chrome`）。
  标题栏 + 左侧栏用它，主区保持纯白：**靠底色差分层，不加任何分割线**。
- 侧栏选中态在灰底上不能再用 `bg-neutral-100`（更脏），改**纯白浮起**：
  `bg-white + ring-1 ring-black/[0.04] + shadow-[0_1px_2px_rgba(16,24,40,0.06)]`；
  hover 用 `bg-black/[0.04]`，标题栏按钮 hover 同理改黑叠加。

   `.icon(app.default_window_icon().cloned())`。
2. **`Menu::get` 的参数不是 `&str`**：签名是 `get<'a, I>(&'a I)` 且约束
   `MenuId: PartialEq<&'a I>`，所以正确写法是 `menu.get("stop")`（I=str），
   写成 `menu.get(&"stop")` 会变成 `&&str` 编译失败。
3. **菜单项文字/可用态要走主线程**：在 ticker 线程里直接 `set_text` 不可靠，
   用 `app.run_on_main_thread(...)` 包一层。`TrayIcon` / `Menu` 本身可 Clone + Send。
4. **`Menu::get` 返回 `MenuItemKind`**，要 `.as_menuitem().cloned()` 才能 `set_text` /
   `set_enabled`。
5. **`Select-String`/管道会让后台任务的退出码失真**：`cargo test ... | Select-Object -Last 25`
   报 failed 但实际 82/82 通过。判基线要看 `test result:` 那行或单独取 `$LASTEXITCODE`，
   别只信任务状态（本轮因此被误判「跑失败」，白查一轮）。

### 验收时发现的真问题：必须单实例
- 现象：关掉再开，界面显示「服务已停止」，日志里
  `HTTP 服务异常退出: 绑定 127.0.0.1:8848 失败（端口被占用？）`。
- 根因有两层：
  1. **进程名是 `OCR Studio`（带空格）**，不是 `ocr-studio`。按 exe 文件名小写找进程
     一个都匹配不到，所以我 Stop-Process 根本没杀掉旧实例。
  2. 程序本身没有单实例保护，双击两次就会有两个进程抢 8848。
- 修复：加 `tauri-plugin-single-instance = "2"`，**必须是第一个注册的插件**，
  回调里把已有窗口 show+unminimize+set_focus（跨进程把参数转交过来）。
- 验收：`scripts/verify_tray.py` 里加了「重复启动进程数 1 -> 1 且服务仍正常」，通过。
