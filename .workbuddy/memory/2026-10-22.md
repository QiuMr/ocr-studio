## M3.2 YOLO 检测引擎（完成并提交 c78b006）
- `models/detect/yolo/v8/`：官方 yolov8n.pt → ultralytics 导出 opset12/640 → model.onnx

- `src/engine/yolo.rs`：letterbox 复刻 ultralytics（**Python round() = 银行家舍入，
  Rust 用 round_ties_even**；缩放直接复用 ocr::preprocess::resize_bilinear 的 cv2 逐位复刻；
  114 填充）、v8 [1,4+C,N] 转置解码（v5/v7 [1,N,5+C] obj×cls 路径已写**未实测**）、
  class-aware 贪心 NMS（conf 0.25/iou 0.7/max_det 300）、先 NMS 后还原坐标、clip 闭区间 [0,w]。
- `/vision/detect` + Tauri vision_detect；错误码 1002（不支持能力）/1003（未知引擎）落地。
- 前端：测试台检测形态（类别 id 徽章着色 + 置信度 + 坐标列表；图上框文字=「类别 置信度%」；
  检测模式隐藏方向分类开关）。
- **逐框对齐验收：tests/yolo_parity.rs 8/8 框 IoU=1.0000、conf 差=0.0000。**
  关键教训：第一版用 bus.jpg 比对 IoU 只有 0.97~0.999——是 **JPEG 解码器 ±1 差异**
  （cv2 vs image crate 的 IDCT），不是我们的 bug；换 PNG 后全归零。以后跨引擎对齐一律用无损图。
- **ultralytics 会按发行版名找 `onnxruntime`，找不到就自动 uv 装最新版**，
  半途 dll 被锁会把新 wrapper 盖在旧 native 上（`is_webgpu_graph_capture_enabled` 属性缺失），
  每跑一次坏一次。已卸 onnxruntime-directml、装 onnxruntime==1.24.3 根治；
  代价：本机 RapidOCR 等 Python 脚本退回 CPU 推理。
- 测试基线：cargo test --lib 63 通过；--ignored 21 项全绿（PP-OCR 基线 pipeline_match 仍逐字全对）。
