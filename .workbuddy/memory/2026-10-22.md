## 第四轮：检测模型可自定义 + 类名从模型读 + 外壳浅灰

用户三点要求：① YOLO 应该能选自己的模型；② 类名最好从模型里自己读；③ 标题栏和左侧栏
换成「大家都用的那种稍微灰一点」的颜色。

### 1. 类名从 ONNX metadata 读（关键发现）
- ultralytics 导出 ONNX 时会写 model metadata：`names = "{0: 'person', 1: 'bicycle', …}"`、
  `task = detect`、`imgsz = [640, 640]`、`description`。ort 侧直接
  `sess.metadata()?.custom("names")` 就能拿（`ort 2.0.0-rc.15` 的 `ModelMetadata::custom`）。
- **不需要 labels.txt**。优先级：metadata > labels.txt（同目录 / 同名 .txt）> `class_{id}`。
- `names` 是 Python dict 的 repr，要自己解析：数字 key、单/双引号、`\'` 转义、
  乱序 key、值里带数字（`'person 2'`）。写了个小状态机 `parse_names`，7 个单测。
- **顺带用 `task` 拦非检测模型**：segment/pose/obb 的输出多 32 个 mask 系数或关键点通道，
  按 `4+classes` 解不会崩、只会给错类别的框 —— 比报错难查得多。
- 实测：把 `labels.txt` 整个移走，检测仍输出 person/bus（证明走的是 metadata）。

### 2. 多模型 + 任意路径
- `catalog::list_yolo_models(root, external)`：扫 `detect/yolo/` 下**所有** `*.onnx`
  （含一层子目录），再并上 config 的 `detect_models`（绝对路径列表）。
- id = 文件名；撞名退到「父目录/文件名」再撞加序号。**第一个 = 默认模型**，
  spec 用不带 id 的 `yolo`（与 `/engine/list`、前端下拉缺省值、pipeline 缺省值一致）。
- **外部模型名不能「像版本号」**（如 `v8.onnx`）——`EngineSpec::parse` 会把 `yolo:v8`
  当旧写法吃掉，所以 `unique_id` 对 external 跳过这类 id。
- 文件选择框用 Win32 `GetOpenFileNameW`（windows crate feature
  `Win32_UI_Controls_Dialogs`）。**`lpstrDefExt` 必须先绑变量**：
  `PCWSTR::from_raw(wide("onnx").as_ptr())` 会指向已 drop 的临时 Vec。
- `save_config` 里必须**保留后端自己维护的 `detect_models`**（前端带的是旧快照），
  否则「刚加的模型」会被下一次保存冲掉。与 `webview_compat` 同理。

### 3. 类名回填（不加载模型就读不到）
- `/engine/list` 是纯目录扫描，读不到 metadata 里的类名（要建 session 才行，几秒+显存）。
- 新增 `AppState::engine_status_list()`，**HTTP 与 IPC 共用一份**（原来两处几乎重复，
  很容易只改一处导致两端不一致）。引擎加载过后回填 classes + 把 note 里的
  「类名在加载时读取」换成「已加载 N 类」。

### 4. 外壳配色
- `styles.css` 加 `--color-chrome: #f7f7f8`（Tailwind v4 @theme → `bg-chrome`）。
  标题栏 + 左侧栏用它，主区保持纯白：**靠底色差分层，不加任何分割线**。
- 侧栏选中态在灰底上不能再用 `bg-neutral-100`（更脏），改**纯白浮起**：
  `bg-white + ring-1 ring-black/[0.04] + shadow-[0_1px_2px_rgba(16,24,40,0.06)]`；
  hover 用 `bg-black/[0.04]`，标题栏按钮 hover 同理改黑叠加。

## YOLOE 运行时提示（#74）—— 导出三件套落地

用户要求「YOLOe 的图找图和语言找图」。之前 #70 做的是**导出时烘焙提示**（换目标要重导），
这轮做**运行时提示**：提示向量 `pe` 作为检测器的第二张图输入。

### 配方（已逐项数值验收，脚本 `scripts/export_yoloe_prompt.py`）
产物在 `models/yoloe/`：

| 文件 | 输入 | 输出 |
|---|---|---|
| `yoloe26n_prompt.onnx` 11.6MB | `images[1,3,640,640]` + `pe[1,80,512]` | `output0[1,300,38]` + `proto` |
| `yoloe26n_vpe.onnx` 11.9MB | `ref[1,3,640,640]` + `vp[1,Q,80,80]` | `vpe[1,Q,512]`（**Q 动态**） |
| `yoloe26n_texthead.onnx` 6.3MB | `feat[N,512]` | `pe[1,N,512]`（opset 13） |

验收：视觉编码器逐值差 1.5e-7；提示头 1.8e-7；端到端（参考图→vpe→检测器）
IoU=1.0000、分数差 5.96e-8。

### 六个必踩的坑
1. **不能 fuse**。`exporter.py:524` 会把 `model.pe` 融进 cv3/cv4 并把 `reprta` 换成
   Identity，那样 `pe` 就不再是输入。完全绕开 fuse。
2. **`pe` 走 `vpe` 形参**。`YOLOEModel.predict` 里 `get_vpe` 对 `ndim==3` 的 vpe
   **直接透传**，而 `get_cls_pe(tpe=None, vpe=pe)` 恰好等于 `pe`。所以
   `model(x, vpe=pe)` 就是「用 pe 当类别提示」，不用改 ultralytics 一行。
3. **必须给 topk 打补丁**。`Detect.get_topk_index` 里
   `idx = ori_index[torch.arange(B)[..., None], index // nc]` 是**两个索引张量**的
   高级索引，torch.onnx 警告后会**错误地** trace 成 Gather → 每行取到同一个 anchor，
   框全一样。改成 `torch.gather(ori_index.squeeze(-1), 1, index // nc)` 即忠实。
4. **`export` 标志要铺到所有子模块**。head 的 forward 读的是 head **自己**的
   `self.export`，只设顶层会返回 `(y, preds)` 并拖出一堆中间张量当输出。
5. **pe 固定 80 槽**（= yoloe-26 原生 nc）。head 内部 `F.normalize(w)`，补零行归一化成
   0 → 分数恒为 bias(-10) → sigmoid≈4.5e-5，天然低于任何阈值；输出形状仍是
   `[1,300,38]`，**与烘焙版一模一样，Rust 解码器不用改**。
6. **topk 输出不能逐值对照**。end2end 输出是 top-300，尾部全是近并列的低分框，
   排序在 torch/ort 间不稳定（零 pe 时尤其严重）。验收只能「置信度过滤 + IoU 匹配」，
   逐值对照永远不通过。这正是项目里那条「误检框置信度是混沌的」。

### 文本塔导不出 ONNX —— 改用纯 Rust crate
`mobileclip2_b.ts` 里嵌的 TorchScript 图**缺张量秩信息**，legacy 导出器在
multi_head_attention 的 `unflatten(-1, [3, size])` 上抛
"transpose for tensor of unknown rank"；换 torch 2.4 的 dynamo 导出器
（需 onnxscript，**必须 0.1.0**，0.7.2 的 `onnxscript.values.ParamSchema` 已被删）同样失败，
把 batch 改静态也没用。

**解法**：用 crates.io 上的 **`mobileclip2-b-rs` 0.1.0**（MIT，基于 candle）——
纯 Rust 的 MobileCLIP2-B 文本编码器 + **CLIP BPE 分词器**，文档明写「used by the YOLOE
text path」，且已对官方 Python/OpenCLIP 参考做过数值对齐（COCO-80 类名最大差 5.2e-7）。
本项目已加依赖：`default-features=false, features=["text","ts-loader"]`。
`cargo check` 通过。所以文本塔**不导 ONNX**，只在 Python 侧导 `reprta` 提示头。

资产（按需下载，不进分发包）：
- `mobileclip2_b.safetensors` 253.7MB（纯文本）或 ultralytics 的 `mobileclip2_b.ts` 253.8MB
- `tokenizer.min.json` 1.5MB

- YOLOE-26 的 `text_model` 是 **`mobileclip2:b`**（不是 `mobileclip:blt`）→ 权重是
  `mobileclip2_b.ts`，别下错（第一次就下错了 599MB 的 blt）。
- `cv2.imread` 读不了本项目的中文目录，一律 `np.frombuffer + cv2.imdecode`。

### 本轮新踩的坑（前面六个之外的）
1. **图输出符号维度必须冻结**。end2end 的 topk 形状 torch 推不出来，导出后
