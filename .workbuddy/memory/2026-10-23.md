## #75 界面精修：圆角 / 按钮尺寸 / 字号统一

### 问题（审计结果）
全站 `*.tsx` 里圆角混着 **7 个自定义像素值**（9/10/11/12/13/14/16px）+ Tailwind 默认的
sm/md/lg/xl，同一个「卡片」在不同页面圆角都不一样；字号混着 **4 个半像素值**
（10.5/11.5/12.5/13.5px）+ 10/11/12/13/14/15/16/26/27，共 13 档。半像素值在 100%
缩放下发虚，差 0.5px 的两档放一起既看不出差别又显得不整齐。

### 做法：覆盖 Tailwind 默认档，而不是逐处改
`src/styles.css` 的 `@theme` 里直接覆盖 `--radius-*` 与 `--text-xs/sm`，
这样既有的 `rounded-md/lg/xl`、`text-sm/xs` 类名**自动归位**，不用动 200 多处调用点。

圆角四档（规则：容器越大圆角越大；子元素比父元素小一档）：
| token | 值 | 用途 |
|---|---|---|
| `--radius-sm` | 6px | 浮层里的小项（下拉选项）、行内代码、微标签 |
| `--radius-md` | 8px | 按钮 / 输入框 / 下拉触发器 / tab / 导航项 / 窗口按钮 |
| `--radius-lg` | 10px | 卡片内部的块：分段控件容器、滚动区、提示条、搜索框 |
| `--radius-xl` | 14px | 卡片 / 面板 / 独立浮层 / 大块容器 |

刻意保留默认值不走梯度的两档：`rounded-full`（胶囊/圆点）、`rounded`=4px
（≤24px 的微图标按钮、浮层微角标、截图上的框标记）。

字号七档（只留整数）：10 微角标 / 11 次要 / 12 正文 / 13 强调正文·卡片标题·按钮 /
14 强强调 / 16 小节标题 / 26 页面主标题·大数字。

### 抓到第三个真 bug：multipart 上传 >2MB 必失败
`routes.rs` 里 `MAX_BODY = 32MB` **只传给了 `to_bytes`**（JSON 路径自带上限），
而 multipart 走的是 axum 的 `Multipart` extractor，它读 `DefaultBodyLimit`
—— **axum 0.8 默认只有 2MB**，且路由层压根没设这个 layer。

实测（1800×1800 随机噪声图 9.73MB）：
```
JSON base64（12.98MB body）  → HTTP 200 ✓
multipart   （9.73MB body）  → HTTP 400 「Error parsing multipart/form-data request」 ✗
multipart   （42KB 小图）    → HTTP 200 ✓
```
**用户影响**：README / 使用说明都写着「支持 multipart」，用户用
`requests.post(files=...)` 传一张 3MB 截图就 400，报错还含糊，只会以为是自己代码错。
修法：`build_router_with()` 里显式加 `.layer(DefaultBodyLimit::max(MAX_BODY))`。
并在 `verify_packaged.py` 加一条 >2MB 大图 multipart 用例钉住（防回归）。

## #87–#94 中文找图 + AI 操控服务（用户：「语义找图只能用英文？没法用中文吗」）

### 需求
1. 语言找图不能只支持英文（用户全是中国用户）；
2. 照 WPE Lab 的模式做「本机 HTTP 服务 + AI 直接调」，**明确不要 MCP**（小白嫌麻烦）。
   拍板：中文方案=词典+中文视觉参考库；接口地址=复用 8848；AI 权限=全选。

### 中文为什么不能直接喂文本塔（原理性，非工程懒惰）
MobileCLIP2-B 是 CLIP 英文语义空间：中文被 BPE 拆成 UTF-8 字节片。
实测 19 个常见中文词只有「人」偶然撞中（0.569，英文的 62%），其余全 0。
换中文文本塔不可行——特征空间与 YOLOE texthead 不对齐。

两条工程路子（都做了）：
- **词典** `engine/zh_words.rs`：内置中英词表（COCO 80 + 常用 UI 词）+
  `models/yoloe/zh_words.json` 用户覆盖。命中→映射英文进文本塔，类名回显中文；
  查不到→400 带相近中文词建议。
- **中文参考库** `engine/prompt_refs.rs`：框一次起中文名 → 走 VPE 图找图通道，
  不依赖 242MB 文本塔。存 `<数据目录>/prompt_refs/`（整张参考图，不裁小块）。

### 架构教训（本轮最重要，动引擎层前必读）
**`prompt.rs::text_pe` 必须保持纯净，中文映射只能放 API 边界的 `pe_for_words`。**
`text_pe` 是官方文本塔的逐位复刻——`yoloe_prompt_parity` 拿它对着 TorchScript
抠数值，而**基线夹具的 words 里故意混了中文词「确认按钮」**（测的就是官方
byte-token 行为）。一开始把词典解析加进 `text_pe`，parity 直接 FAILED。
分层后 parity 3/3 全绿。

### AI 操控服务（`api/ai.rs` + `api/ai_tools.rs`，复用 8848）
- 19 个工具：状态/清单/引擎/配置/日志/目标/截屏/认字/找词/找图/扫码/教目标/
  启停服务/改端口/改级别/改设备/改阈值。三风险档 readonly/write/dangerous。
- 信封 `{ok, summary, data, error}`：消费者是大模型，`summary` 是转述用户的人话，
  `error` 必须告诉 AI 下一步怎么做。
- Bearer 连接码（FNV 哈希混时间/pid/序号/ASLR 地址，不引 rand）+ 常数时间比较；
  `request_id` 幂等（回放 200 条 + inflight 占位，键用 `\x00` 分隔防撞键）；
  120 次/分钟滑动窗口限流；写操作审计日志。
- `closest_tool`：AI 写错工具名时给最接近候选（前缀优先，其次编辑距离 ≤3）。
- **刻意不进 `routes.rs` 的 `PATHS`**：那张表是「用户脚本能用哪些接口」的清单，
  AI 入口混进去会污染接口文档页。`/ai/v1/*` 默认关，403 文案指路「设置 → AI 控制」。
- 设置页「AI 控制」面板：开关/地址/连接码（复制/重置）/一键复制提示词/已教目标列表。

### 端点计数口径
`/vision/promptref` 一个路径三种方法：后端 `PATHS` 按路径算 19，
前端 `ENDPOINT_PATH_COUNT`（`new Set(paths).size`）对齐——不能取 `ENDPOINTS.length`。

### 收尾修的真问题（打包验收跑出来的）
1. **`DELETE /vision/promptref` 只认 JSON body**：`curl -X DELETE "...?name=中文"`
   是 REST 惯例也是 AI 最自然的写法，却吃一个「JSON 解析失败」，报错还指向
   完全不相干的方向。改为 query 优先、body 兜底（加 `serde_urlencoded` 直接依赖，
  axum 传递依赖零编译成本），补 4 种传参单测钉住。
2. **`verify_packaged.py` 自身两个 bug**：query 中文没 percent-encode（urllib 按
   ascii 发不出去）、`bytes` 与 `str` 比较 TypeError。脚本的锅别怪产品。
3. **`.gitignore` 漏 `src-tauri/config.json`**：`AppState` 默认 data_dir=`.`，
   测试/运行期会把配置（含 AI 连接码）写到 src-tauri/，差点进仓库。补
   `src-tauri/config.json` 与 `prompt_refs/`。

### 环境坑（本轮）
- **rlib 损坏不都是瞬时的**：`-j 2` 并行 + 可用内存仅 3.5GB（多个 IDE 进程）时，
  `libocr_studio_lib.rlib`（489MB）真被写坏，且会级联报 serde/image「页面文件太小」。
  处理：杀僵尸 rustc → 删损坏 rlib → **`cargo test --no-run -j 1` 分步编译** →
  `-- --ignored --test-threads=1` 串行跑。一步到位直接 test -j 2 会反复踩。
- `pack_exe.ps1` 的 `Remove-Item` 对构建产物抛 safe-delete trash fail-closed
  （detail 显示 OK 仍拦）→ 用 `Remove-BuildArtifact`（.NET 直删），语义上也更对。
